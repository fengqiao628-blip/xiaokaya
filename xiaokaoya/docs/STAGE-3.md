# 第三阶段实施范围

版本0.3.0，数据库V3。第二阶段已验收。只开发年度周期档案、三个独立状态维度、学习资料和章节基础管理，不提前开发日历计划、计时器、音效或动画。

## 结构和迁移

保留V1/V2表及记录，V3追加：

- cycleStatuses：id等于cycleId；报名/参考状态（未计划、计划报考、已报名、已参加）与考试结果（未记录、通过、未通过）、考试日期、备注及修订号。学习状态继续独立保存在cycles。
- materials：所属年度周期、名称、教材/视频类型、版本说明、综合试卷子项、排序、归档时间及修订号。
- chapters：所属年度周期、综合试卷子项、名称、排序、章节完成状态、独立1—5星掌握程度（可未评）、备注、归档时间及修订号。
- materialProgress：同周期资料与章节的进度，组合唯一，0—100整数百分比及修订号。教材和视频可以分别记录；完成情况与掌握程度不互相推断。

每个年度使用独立周期及子记录，资料和章节不能移动到另一年度。综合试卷一、二仍为内部子项，不增加一级科目。暂停、归档不删除历史；只有显式恢复才取消归档。按名称或年份修改的操作不暗中改写其他年度。

升级先用原生API一致性读取旧库、保存并回读验证全量快照，再持久化迁移日志并授权原子版本事务。旧周期默认未计划报考、结果未记录；旧表逐行保留。V1、V2均可直升V3，事务失败保留旧版本及旧行。

备份格式继续为1，schemaVersion区分数据库结构；保留V1/V2精确校验规则。旧备份在内存中补齐默认状态及空的新表，原文件不变；完整恢复仍先保护、单事务替换、复核和回滚。旧备份恢复会整体替换当前新增的资料章节，预检必须展示这些表的数量。未来版本拒绝导入，不能静默丢字段。

未完成的旧版恢复日志先按原版本回滚或核对，再启动结构迁移。Windows正式人工验收只从桌面/开始菜单进入，避免工具环境的AppData重定向；自动化只用项目隔离profile。

## 页面与验收

“我的科目”进入年度档案管理，可按年度和考试体系筛选，包括暂停/归档的历史周期；保留原批量选科入口。周期详情提供独立状态设置、资料清单、章节列表、进度输入、星级评估及归档恢复。任务可关联同年度章节，历史关联保留。

重点验证：同科2027/2028/2029独立；状态更新互不替代；恢复归档不推断学习或考试状态；教材100%不提升掌握星级；综合试卷关联正确；跨周期进度/任务关联拒绝；旧编辑冲突不覆盖新数据；归档后旧任务、进度、实际时长保留；V1/V2升级与导入；迁移/恢复故障回滚；新版JSON和CSV包括新增数据；关闭重开、离线和窄屏。

新增字段和表均纳入完整备份。appId、NSIS GUID、userData、sessionData、origin、Session及数据库名称沿用原合同。
