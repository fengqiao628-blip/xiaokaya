# 第七阶段方案：伙伴互动、语库与 Windows 发布

方案日期：2026-11-16；实现更新：2026-11-17。第六阶段0.6.0已完成用户验收，源码、安装包、转发ZIP、编译ASAR及摘要已冻结在`.runtime/baseline/stage-6`。用户了解V5→V6原因及风险后确认方案，补充多版本状态鼓励语，并要求继续开发。现已实现0.7.0/V6、通过153项单元/数据测试与40项真实Electron流程；原安装已覆盖更新，未自动启动，待原桌面入口首次打开及用户验收。JSON封装格式仍为1。

用户要求重大数据结构、存储路径、升级和备份策略调整先说明原因与风险。本阶段需要持久化作者出处、收藏、自定义语句及声音/动画偏好，现有V5只有语句正文、分类、每日分配和历史，缺少上述数据。建议增加V6结构，不把结构化数据塞入现有备注或分类字段。

## 产品范围

- 五位现有伙伴增加轻微呼吸、眨眼、学习、休息、短暂庆祝和点击回应。继续使用本地SVG素材及统一状态接口，通过配置映射素材、动作和声音，新增动物不要求修改任务业务分支。
- 短音效对应开始、暂停、任务完成、到时及点击回应，默认总静音。提供总开关、音量、伙伴音效和到时提示开关；总静音始终优先。首版采用自行制作的短音效，不依赖在线语音服务或运行时下载。
- 动画可关闭，默认跟随系统减少动态效果设置。声音/素材播放失败只影响体验，不阻断计时、保存、备份或恢复。学习过程没有持续循环叫声。
- 本地语库以约200条为目标，包含原创鼓励、可核实出处的名言和古典诗词；宁缺毋滥。显示类别、作者、作品与出处，可查看详情、收藏、查历史及自定义。实施时核对原文和署名，将来源随程序保存；自定义来源标注为用户填写。
- 固定每日一句在同日刷新、关闭重开、升级后保持原选择；主动换一句保存结果。开始、暂停、完成等动态鼓励单独显示，不覆盖每日一句。自定义修改或归档不改写过去已经展示的正文和出处。
- 保留阶段5计时与阶段6统计口径；Windows交付继续为离线NSIS安装包和可微信转发的ZIP，更新安装、升级、卸载和备份说明。

第一期仍为阶段1—7。错题、模拟考试、冻结历年报告和长期数据验证继续留在阶段8；云同步及多设备冲突不加入。

## 伙伴的小声鼓励补充

用户2026-11-16要求增加随学习状态变化的多版本文案。例如学习中显示“坚持就是胜利”，学习结束显示“辛苦了，今天的你也很棒”。这部分作为独立的本地状态语库，与约200条每日一句/名言诗词库分别管理，不用重复短句充当每日语库扩容。

- 覆盖准备开始、开始学习、持续专注、暂停休息、继续学习、倒计时到时、结束本段、任务完成、当天目标完成及点击回应，每类首批至少12种，合计至少120条。
- 状态变化及时切换到相应文案；学习过程中最多每5分钟温和更换一次，可手动“换句鼓励”。同类循环在用完之前不重复，不因页面重渲染或计时每秒心跳反复跳字。
- 到时只说“这一段时间到了，先休息一下”，结束本段只肯定投入；只有用户确实勾选任务完成，才出现任务完成类祝贺。中途暂停不使用责备、比较或催促文案。
- 五位伙伴使用统一状态接口，文案可搭配伙伴签名。声音采用独立短音效开关；“小声鼓励”指文字陪伴，不自动逐句语音朗读。
- 不覆盖每日一句，不写入或改动学习时长、任务完成状态和每日语句历史；全部离线可用。增加这部分文案本身不额外增加数据库表或升级要求。

## V6 数据设计（原方案）

保留V1—V5已发布schema及其校验规则，新增V6，不修改已发布结构定义。现有任务、记录、片段、计时、档案、周计划、偏好行及统计算法不改写。

| 数据 | 设计与保留规则 |
|---|---|
| 原`quotes` | 继续保存稳定ID、正文、分类；保留原q1—q8，不按数组位置重新编号。新增内置语句与自定义语句使用不同ID命名空间，旧ID冲突不覆盖。 |
| 新`quoteDetails` | 按语句ID关联，保存类型、来源类别、作者、作品、可核对的出处及链接、归档时间、修订信息。仅准确匹配内置ID及正文时赋予内置署名；其他旧数据不猜测作者。自定义删除采用归档，保留历史引用。 |
| 新`quoteFavorites` | 按语句ID保存收藏状态和修订信息；反复收藏/取消幂等，不复制语句，不改动正文。 |
| 新`experienceSettings` | 唯一体验设置记录：总声音开关默认关、音量、伙伴音效/到时提示选择、动画偏好（跟随系统/开启/关闭）及语句类别偏好。保留原`preferences`中的伙伴选择与周目标。 |
| `dailyQuotes`与`quoteHistory` | V6允许可选的出处快照；新展示记录保存当时的作者/作品/来源，与已有正文快照一同保留。旧记录原样保留，没有出处快照时不把当前可编辑署名冒充历史出处。 |

新表加入完整JSON、数量预览、引用校验、摘要计算和整库恢复。出处快照也纳入严格校验与摘要。恢复保留收藏、归档、自定义与体验设置；CSV仍用于查看，完整恢复继续使用JSON。新增语库导出可按实际界面需要提供，既有原始CSV和统计CSV继续保留。

语库增量更新必须使用确定的稳定ID与纯转换，在预检和实际迁移中得到相同结果；不会在恢复提交后悄悄补写语句，导致“与本机一致”判断失真。V6完整备份按备份内容恢复；V1—V5备份在暂存数据中补齐确定的V6默认结构，并清楚提示版本转换。未来扩充内置库仍需显式、幂等更新，不覆盖用户内容或已分配每日语句。

## 升级、备份与风险

1. 继续使用当前独占安全操作入口。升级前导出旧schema完整保护快照，落盘回读核对SHA-256，通过后才授权数据库升级；保存失败、空间不足或回读不一致时停止升级。
2. 先用纯转换生成V6预期数据并校验引用、设置范围、原有业务行及目标摘要，写入安全日志后，在IndexedDB版本事务内创建新表、加入默认体验数据与新增内置语句，并记录迁移。既有业务行保持原值。
3. 事务中途失败由IndexedDB回滚，旧版本数据保留。提交后逐表/摘要复核；重开按安全日志区分已完整提交、未提交与状态异常。异常无法证明一致时停止写入，保留原库、日志和保护快照，不自动删库重建。
4. 恢复前仍创建并验证当前整库保护快照；恢复写入与失败回滚涵盖全部V6表及出处快照。恢复和首次启动只建立状态基线，不重播任务庆祝或到时音效，也不补记学习时间。
5. **升级成功后旧0.6.0不能直接读取V6库。覆盖安装旧程序不等于数据库回退。** 如需退回旧版，必须基于保留的V5完整备份和已验证的恢复步骤处理，不能要求用户直接覆盖数据库文件。安装说明需明确这一限制。

主要风险是新增表遗漏备份、旧引用丢失、迁移中断，以及声音重复触发。通过全量表清单、旧库逐行对比、完整往返/故障回滚、稳定事件ID及启动/恢复抑制播放验证。现有21分钟实际学习与1分钟陪伴应保持不变；用户后续正常新增学习记录除外。

存储与安装合同全部保持：`cn.xiaokaoya.study`、NSIS GUID `d0a54531-87fa-48d9-94d0-ef98f93ca48c`、`%APPDATA%\Xiaokaoya\`、其`profile`子目录、standard/secure的`app://xiaokaoya`、默认持久Session及`XiaokaoyaStudy`数据库名。安装包只替换程序资源，不携带用户数据库；卸载保留用户目录。

## 事件与离线边界

伙伴动画及声音读取计时服务和任务成功提交事件，不参与时间计算。开始、暂停、到时、完成、点击采用稳定事件键，重新渲染或计时心跳不重复播放。初次加载、旧记录读取及备份恢复不作为新的完成事件。总静音立即停止当前声音并阻止后续播放；切换伙伴不重置计时或改动记录。所有素材与出处文本本地打包，不通过远程页面或网络脚本执行。

## 验收标准

- 五位伙伴分别可见学习/休息/庆祝/点击回应；动画关闭及系统减少动态有效；声音默认关闭，开启后音量/分项开关正确，总静音立即生效且没有重复提示。

- 语库类别、署名及出处清楚，内置ID唯一；收藏、自定义、归档、历史及设置重开保留。当天固定句不因重开或升级改变，主动更换可持久保存；编辑自定义内容不改写旧正文/出处快照。

- 回归现有单元及真实Electron流程；离线、窄屏、素材/声音失败降级、开启计时后切换页面、重开/恢复不重播事件可验证。
