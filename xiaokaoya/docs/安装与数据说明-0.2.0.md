# 小考鸭 0.2.0 · 安装、升级与数据安全

本版本为第二阶段验收版。先使用测试数据核对备份和恢复，完成人工验收后再正式积累长期记录。学习记录录入、计时器等仍按后续阶段交付。

## 安装与打开

1. 解压 ZIP，双击 `Xiaokaoya-Setup-0.2.0-x64.exe`，也可直接使用单独安装包。
2. 默认按当前 Windows 用户安装，从桌面或开始菜单的“小考鸭”打开。无需 Node.js、浏览器地址、服务器或账号。
3. 资源随包提供，可离线使用。当前为 Windows x64 包，未签名，系统可能提示未知发布者；请核对来源和 SHA256，不要关闭系统防护。

安装、升级后的人工使用与验收统一从 Windows 桌面或开始菜单进入。开发工具自动启动的程序可能继承工具的 Windows 应用隔离环境，实际使用另一份数据；即使界面显示的 AppData 路径相同，也不能据此确认是同一数据集。遇到不同任务、伙伴或快照时先停止恢复覆盖，分别导出核对，不要删除任一数据目录。

## 从 0.1.0 升级

1. 保存输入并关闭旧版，运行新版安装包。安装身份不变，程序文件更新，数据目录保留。
2. 首次启动先把 V1 数据一致性导出为“升级前保护”快照，写入及回读验证成功后才执行 V1→V2。
3. V2 只追加数据集标识与迁移记录，不改写旧科目、任务、伙伴、励志语等业务记录。
4. 失败时程序停止正常写入，请保留数据目录、快照和提示。不要清空数据库，也不要用旧程序强行打开已升级的数据。
5. 成功进入后先核对旧任务，再导出完整 JSON 到其他磁盘或设备。

## 数据位置

- userData：`%APPDATA%\Xiaokaoya\`
- sessionData：`%APPDATA%\Xiaokaoya\profile\`，IndexedDB 在其中由 Chromium 管理。
- 自动/手动快照：`%APPDATA%\Xiaokaoya\backups\`
- 开发和自动化测试使用项目 .runtime 内的隔离目录。
- “关于与数据”显示实际路径，“数据与备份”可打开快照文件夹。

不要把运行中的 IndexedDB 底层文件拷贝当作一致性备份。完整 JSON 是推荐的跨电脑恢复格式。

## 导出完整 JSON

点击“数据与备份”→“导出完整 JSON”并选择位置。程序一致性读取全部表，写入并回读验证后才提示成功。

包含当前已实现的全部业务表、年度周期、任务、实际记录及时间明细、偏好、励志语和历史、数据集标识与迁移记录；不递归打包快照目录、日志和导出回执。以后增加业务表必须同步增加备份清单和版本测试。

建议定期另存到电脑之外的设备。“最近导出”是历史回执，不代表文件之后没有被移动或删除。

## 预检和完整恢复

1. 点击“选择 JSON 预检”，或在快照列表点“预检”。此时不改变学习数据。
2. 检查格式、版本、SHA-256、记录数、重复主键、关联、状态、日期、计时来源和重叠。
3. 核对“当前本机”与“恢复后”数量。不同数据集额外提示；只提供整体替换，不自动合并。
4. 内容一致显示“无需恢复”，不新增记录。相同文件在本机内容变化后仍可用于恢复旧状态。
5. 勾选整体替换确认，点击“先备份，再恢复”。先创建并验证恢复前快照；失败则停止，不清空任何表。
6. 在覆盖全部表的一个事务中替换数据，随后复核。失败时回滚；不能确认结果时暂停写入，重新打开先检查安全日志。
7. 恢复会替换导出之后的新增和修改。需要找回时，预检对应的“恢复前保护”快照，再确认恢复。

损坏或不支持的文件不会写入。V1 快照在暂存数据中转换为 V2，原文件不变。仅时长补录注明无法核验重叠；未结束计时保留为待确认，不自动继续或累计。

单个文件支持到256MB，超出明确停止，不截断。SHA-256 用于发现损坏，不证明文件来源可信。

## 本机快照

- 每个数据集每天首次使用创建一份，午夜跨日也会检查。
- 最多保留14份日常快照；新快照验证后才轮换旧的已验证日常文件。
- 升级前、恢复前和手动快照不自动删除。无法验证的文件保留并提示。
- 重要操作的快照失败会阻止操作。日常快照失败明确提示，不重置数据库。
- 本机快照不能代替外部备份，也不能防止整机或硬盘损坏。

## CSV

选择任务、学习记录或科目周期，点击“导出 CSV”，用 Excel 或记事本检查中文表头。正确处理引号、逗号、换行，并防止用户文本被当作公式执行。

预计与实际分钟分列，无实际记录时为0。CSV 不含完整关联与设置，不能代替 JSON 恢复。

## 卸载、重装及换电脑

普通卸载保留 AppData 数据和快照，同一 Windows 用户重装后继续读取。不要额外删除 profile。换电脑、换用户或重装 Windows 前应导出完整 JSON，再在新环境预检恢复。

## 人工验收建议

1. 核对升级后旧任务、伙伴和年度周期。
2. 导出备份 A，预检应显示内容一致。
3. 新增“测试恢复用”任务 B，再预检 A，核对数量差异。
4. 恢复 A，B 消失，原数据保留。
5. 预检并恢复“恢复前保护”快照，B 应回来。
6. 导出 CSV 检查中文、预计和实际时间。
7. 关闭再打开，检查数据和快照。

全程只用测试数据。测试损坏文件请先复制一份，不修改原始备份。
